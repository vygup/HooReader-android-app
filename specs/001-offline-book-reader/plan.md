# План реализации: Офлайн-читалка книг

**Ветка**: `001-offline-book-reader` | **Дата**: 2026-10-01 | **Спецификация**: [spec.md](spec.md)

**Ввод**: Спецификация офлайн-читалки EPUB и FB2 с восстановлением логической позиции.

## Краткое описание

Android-приложение на Kotlin и Jetpack Compose импортирует EPUB и FB2 через Android File Picker,
создаёт собственную локальную копию, показывает библиотеку и отображает содержимое вертикальной
прокруткой. Позиция хранится как глава, абзац и смещение; процент используется только как
приближённый индикатор. EPUB с DRM, сетевые каталоги и OPDS не входят в этот MVP.

## Технический контекст

**Язык/версия**: Kotlin; Android `minSdk 26`.

**Основные зависимости**: Jetpack Compose, Navigation Compose, Room, DataStore Preferences,
AndroidX Lifecycle, Kotlin Coroutines, Readium Kotlin Toolkit для EPUB, `XmlPullParser` для FB2.

**Хранение**: Файлы книг и обложки — во внутреннем app-specific storage; метаданные, содержание и
Reading Position — в Room; тема и размер текста — в DataStore Preferences.

**Тестирование**: JUnit, coroutine-тесты, Room in-memory tests, Compose UI tests и Android
instrumentation tests на эмуляторе или устройстве.

**Целевая платформа**: Android 8.0 (API 26) и выше.

**Тип проекта**: Одиночное Android-приложение.

**Цели производительности**: Обычная книга до 20 MB открывается за 2 секунды на современном
Android-устройстве среднего класса; библиотека из 100 книг и прокрутка читаемого текста остаются
плавными.

**Ограничения**: Работа офлайн после импорта; EPUB только без DRM; без сети, аккаунтов, OPDS,
синхронизации или облачного хранения; не загружать целую большую книгу в memory без необходимости.

**Масштаб и scope**: Один пользователь на устройстве, не менее 100 книг в библиотеке, EPUB и FB2.

## Проверка конституции

| Правило | Статус | Обоснование |
|---|---|---|
| Android, Kotlin и Jetpack Compose | Пройдено | План использует только Android, Kotlin и Compose для UI. |
| Чтение и сохранение прогресса | Пройдено | Логическая позиция — центральная модель данных и критерий приёмки. |
| OPDS внутри приложения | Исключение MVP | Спецификация явно исключает OPDS. Исключение документировано в `checklists/opds.md`; OPDS требует отдельной спецификации и утверждения scope до реализации. |
| Секреты и безопасность | Пройдено | MVP не использует сеть, аккаунты или токены; файлы остаются в app-specific storage. |
| Один commit — одна task | Пройдено | `tasks.md` будет разбит на атомарные tasks. |
| Русский язык документации | Пройдено | Артефакты плана создаются на русском. |

**Результат до Phase 0**: пройдено с документированным исключением OPDS.

## Учёт сложности

Исключение OPDS из текущего MVP не отменяет конституционный принцип. До добавления OPDS требуется
отдельная спецификация с правилами каталогов, аутентификации, токенов и offline-поведения.

**Результат после Phase 1**: пройдено; дизайн не добавляет сетевые зависимости или секреты.
