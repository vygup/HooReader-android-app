# Руководство проверки второго релиза

**Статус**: План проверок после реализации; команды не означают, что новые сценарии уже выполнены.
**Связанные документы**: [spec.md](spec.md), [UI-контракт](contracts/reader-ui.md),
[модель данных](data-model.md).

## Подготовка

Рабочая директория — корень HooReader. Требуются JDK 17–21, Android SDK API 36,
Build Tools 35.0.0 и включённое разблокированное устройство/эмулятор.
Сборочная конфигурация: [docs/building.md](../../docs/building.md).

Основной стенд: API 34+ с настоящим системным увеличением шрифта до 200%.
Совместимость: отдельный API 26. В отчёте указывать модель, API, размеры и density экрана,
режим сборки, font scale и профиль cold/warm. Производительность приёмки измерять также
на физическом устройстве среднего класса; один Pixel_10 AVD её не подтверждает.

Использовать EPUB/FB2 из app/src/androidTest/assets/books и дополнить fixtures длинным абзацем,
главами, кириллицей/Unicode, списками, иллюстрациями, пустой главой и отсутствующим названием.
Подготовить корпус 20 MB обоих форматов для раннего среза, с несколькими главами и поздним anchor.
Не применять очистку данных к пользовательской установке.

## Сборка и автоматические проверки

```sh
./gradlew :app:check :app:assembleDebug :app:assembleDebugAndroidTest
./gradlew :app:connectedDebugAndroidTest
```

Unit проверки должны покрывать reducer интерфейса, settings write queue/defaults,
совместимость preferences, непрерывность slices, инвалидацию индекса и восстановление anchor.
Instrumentation проверяет реальные gestures, измеренные переносы и настоящий reader destination.
Моки навигационного readerContent сами по себе не доказывают подтверждение выхода.

После расширения существующих специальных сценариев выполнить:

```sh
scripts/verify-reader-process-death.sh
scripts/verify-import-corpus.sh /tmp/hooreader-v2-import-corpus.json
scripts/measure-reader-performance.sh /tmp/hooreader-v2-performance.json
```

Скрипт performance сейчас проверяет первый релиз; при реализации его необходимо расширить
холодной и тёплой пагинацией. Process-death сценарии должны дополнительно сохранять выбранный
режим и confirm_reader_exit. Skipped opt-in тесты общего прогона не заменяют отдельные запуски.
Команды предполагают ANDROID_HOME/ANDROID_SERIAL согласно документации сборки.

## Основные сквозные сценарии

1. Открыть книгу. Панели скрыты, сверху глава и процент вертикального режима.
   Первое одиночное касание показывает панели, второе в область книги скрывает.
   Страница/позиция и измеренный viewport не изменяются. По SC-001 выполнить 20 taps и
   100 навигационных gestures каждого режима, включая отменённые, boundary и оба направления.
2. Показать управление, открыть настройки чтения. Выбор режима расположен рядом с масштабом,
   «Готово» отсутствует. Выбрать PAGINATED, закрыть меню через Back, жест и касание снаружи.
   Текущий anchor находится на странице; сверху глава, снизу точный номер, процент скрыт.
3. Свайп влево открывает следующую страницу, вправо — предыдущую. Проверить переходы глав
   и отсутствие пропусков/дубликатов внутри длинного абзаца. На первой/последней странице
   нельзя выйти или зациклиться. Содержание открывает начало выбранной главы.
4. Переключить режимы в середине длинного абзаца; изменить масштаб, ориентацию и системный
   шрифт. Текущий текст остаётся на странице или в пределах одного абзаца вертикально.
   Повторное открытие и завершение процесса сохраняют место, режим, тему и масштаб.
5. Из библиотеки открыть настройки приложения. Защита выхода изначально включена.
   Проверить экранный выход и Back: запрос, отмена/касание снаружи, подтверждение,
   повторные быстрые действия. Закрытие меню сначала закрывает меню; ON_STOP не вызывает запрос.
   Отключить защиту и перезапустить: выход без запроса, позиция сохранена.
6. Запустить те же основные пути в авиарежиме. EPUB и FB2, содержание, настройки и
   восстановление остаются доступны после удаления/перемещения исходного внешнего файла.

## Крупный системный шрифт и визуальная приёмка

SC-008 задаёт матрицу EPUB/FB2 × VERTICAL/PAGINATED × LIGHT/DARK × обе ориентации ×
системный шрифт 100/150/200% × минимальный/максимальный масштаб чтения.
На API 34+ устанавливать реальный размер через настройки Android; подмена LocalDensity
в тесте полезна дополнительно, но не заменяет нелинейную шкалу платформы.

Ожидается: доступны все основные действия, подписи не обрезаны, menu при необходимости
прокручивается, длинная глава сокращается только в указателе, указатели различимы и меньше
основного текста. Книга и указатели не перекрывают друг друга.
Сделать screenshots для обеих тем, обоих режимов и системного максимума.
Проверка 5 участников: минимум 4 самостоятельно используют управление/режимы и различают
указатели по SC-007. TalkBack не входит в приёмку второго релиза.

## Ошибки и восстановление

Использовать test doubles репозитория/загрузчика, не повреждать пользовательскую базу:

- failure записи preferences: выбранное значение видно как pending, сообщение и retry доступны;
  последующий успех другого поля не теряет неуспешное изменение;
- failure flush при выходе или смене геометрии: книга/место остаются, retry не вызывает двойной выход;
- отмена старого расчёта новым LayoutKey: устаревший результат не заменяет текущий экран;
- отсутствующий/повреждённый производный индекс или .part: пересоздание, исходная книга и
  долговечная позиция не потеряны;
- пустая глава/повреждённое изображение: детерминированный fallback и доступ к остальному тексту.

## Производительность и ранний эксперимент

До основной UI-реализации получить вертикальный срез source spool → measurement → page draw.
Для 20 MB EPUB и FB2 записать cold/warm начало и позднюю главу, смену масштаба, ориентации,
системного шрифта 200%, с отдельным новым LayoutKey. Cold означает отсутствие валидного
производного индекса на выделенной тестовой установке.

В отчёте фиксировать:
- время от завершения выбора до первого читаемого кадра и до точного глобального номера;
- количество source passes, resident blocks/layout и peak memory, отсутствие полной List книги;
- размеры page index/spool, отмену работы и состояние frontier;
- время появления панелей и количество действий доступа к меню.

SC-004: ≤0,3 секунды для панелей, ≤2 касаний для содержания/настроек, ≤1 секунды для
завершённого применения параметра. Для постраничной геометрии последняя граница включает
готовую страницу с правильным номером; PreparingPages не является успехом.
Порог измеряется с холодным ключом, а не только с кэшем. Превышение требует оптимизации
перед релизом; текущая спецификация не ослабляется этим руководством.

## Доказательства и завершение

Сохранить quickstart-results.md, performance-results.md и evidence/ с машинными данными
после выполнения. Для каждого SC-001–008 привести сценарий, стенд, результат и ссылку
на доказательство; пройденный запуск измерительного теста не равен пройденному порогу.

Чеклисты принадлежат review требований: их отметки не заменяют результаты приложения.
